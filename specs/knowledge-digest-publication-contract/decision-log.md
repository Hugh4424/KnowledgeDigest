# Decision Log

## 原始需求

KnowledgeDigest 要成为每天可运行的个人和企业知识消化系统。新知识库直接发布为清楚、可导航的知识库；旧知识库只在明确托管范围内新增和更新。Task 1 只交付知识发布合同与离线可读输出。

## 目标

让读者从知识库根目录进入，按分类浏览可读标题和路径的托管主题页；同时保持 Claim、Evidence、Provenance、归档和运行审计完整。

## 范围

- 新知识库初始化读者入口、分类索引和托管主题页。
- 旧知识库只在 `kb.structure.md` 声明目录内新增或更新带托管标记的文件。
- 离线确定标题、首次可读路径锁定、读者导航、托管写入门禁和无 LLM/embedding 的验收。
- 主题页内容重组后仍遵守 300 行、溯源、写前归档和原子写。

## 非目标

- 不删除旧知识库页面；不实现全量对账删除。
- 不让 LLM 成为默认标题或文件名来源；该能力属于 Task 2。
- 不引入数据库、调度器、CAS、journal、AgentMemory、向量库或外部网络。
- 不自动接管没有托管标记的历史输出；既有 116 页结果只作回归样本。

## 决定

### D-01：新库发布与旧库更新

- 问题与最终选择：新知识库直接发布；旧知识库直接更新。
- 推荐状态：用户直接决定；推荐理由是同一合同同时覆盖首次建库和每日增量。
- 大白话：新库开箱可读，老库不会被整库重建。
- 来源：用户回答“新知识库直接发布，老知识库直接更新”。批准绑定：`host-message://reply/talk-round-1-question-1`。
- 事实与约束：正式输出当前只有哈希主题页；手写旧页必须保留。
- 推理：用户每日运行需求 → 需要两种运行模式 → 共享发布合同但不同写入前置条件。
- 影响：`kb.structure.md`、发布布局、写入预检、验收样例。
- 后果与风险：旧库要先声明托管目录；没有声明必须明确失败。
- 拒绝方案：只支持新库，不能满足每日更新；任意旧库整库改写，风险过高。
- 未决项：无。
- Supersedes：none。

### D-02：托管权属与稳定身份

- 问题与最终选择：只管理声明托管目录内，页头同时有 `managed_by: KnowledgeDigest` 和 `digest_topic_id` 的文件。
- 推荐状态：已推荐并由用户选择；避免覆盖手写旧知识。
- 大白话：系统只动自己明确签名过的页，标题和文件名供人看，稳定 ID 供系统更新。
- 来源：用户回答“只管理 kb.structure.md 声明的目录和带 KnowledgeDigest 标记的文件”；“页头保留稳定 digest_topic_id 和托管标记；标题、文件名可读”。批准绑定：`host-message://reply/talk-round-1-question-2`、`host-message://reply/talk-round-2-question-2`。
- 事实与约束：当前写入只校验路径安全，未校验托管权属；当前路径和标题暴露 hash。
- 推理：旧库保护 → 明确权属 → 稳定 ID 与显示名称分离 → 可安全增量更新。
- 影响：页头格式、路径解析、写前验证、Home 和分类索引保护。
- 后果与风险：用户移除托管标记后系统不再写该页；首次迁移未标记旧页不自动接管。
- 拒绝方案：按标题/路径猜测，改名会重复；人工映射表，日常维护成本高。
- 未决项：无。
- Supersedes：none。

### D-03：删除策略已撤销

- 问题与最终选择：旧库只新增和更新，不删除。
- 推荐状态：方向审查建议缩小范围，用户选择修正。
- 大白话：日常同步不能删旧页面；本任务也不做全量对账删除器。
- 来源：用户回答“移除‘删除’需求，旧库只做新增和更新”。批准绑定：`host-message://reply/review-direction-scope`。
- 事实与约束：当前 `writeback` 会处理过期目标路径并删除文件；错误删除会损害旧知识库。
- 推理：可读发布是当前核心交付 → 删除需要独立生命周期与回滚合同 → 本任务禁止 remove。
- 影响：写回计划、分页收缩、旧库验收和 CLI 行为。
- 后果与风险：旧分页不能 `unlink()`；若内容重组后页数减少，旧页需保留并从读者导航移除或更新为托管跳转页，具体规则进入 spec。
- 拒绝方案：日常缺失即删除，误删风险高；实现全量删除，扩大 Task 1。
- 未决项：分页收缩采用“导航移除”还是“托管跳转页”，由 build-spec 选最小无丢失规则。
- Supersedes：Talk Round 2 中“显式全量对账时删除”的暂定选择。

### D-04：离线标题和路径锁定

- 问题与最终选择：首发标题按“已有标题 → 源文件 title/H1 → 文件名”确定；首次可读路径锁入托管元数据，之后改标题不自动改路径。
- 推荐状态：已推荐并由用户选择；兼顾可读和链接稳定。
- 大白话：第一次取一个看得懂的名字，以后标题能改，链接不会乱。
- 来源：用户回答“首发取‘已有标题 → 源文件 title/H1 → 文件名’；首次路径锁进托管元数据”。批准绑定：`host-message://reply/review-direction-title-source`。
- 事实与约束：当前 `identity.py` 固定生成 `topic-<hash>` 路径，`page_layout.py` 把 hash 写进 H1；Task 1 禁止 LLM。
- 推理：离线限制 → 用现有本地标题来源 → 锁定首次路径 → 主题 ID 继续作为更新键。
- 影响：identity、page layout、索引链接、旧页更新测试。
- 后果与风险：原始文件标题差时首发标题也可能朴素；不确定分类进入待归类。
- 拒绝方案：手工结构表覆盖所有标题，维护重；继续 hash 标题，不可读。
- 未决项：无。
- Supersedes：none。

### D-05：LLM 默认标题延后

- 问题与最终选择：默认 LLM 标题和文件名不进入 Task 1，作为 Task 2。
- 推荐状态：已推荐并由用户选择；保持离线验证可重复。
- 大白话：先保证不用模型也能产出可读知识库，再做更聪明的命名。
- 来源：用户回答“不放进 Task 1”。批准绑定：`host-message://reply/review-direction-llm-scope`。
- 事实与约束：LLM 默认会引入 provider、超时、成本、输出校验和真实模型验收；本任务的离线合同禁止网络。
- 推理：发布合同先稳定 → 离线回归可证明 → LLM 语义优化独立评估。
- 影响：Task 1 验收与 Task 2 依赖关系。
- 后果与风险：Task 1 的标题语义不如 LLM；但不会因 provider 失败失去可读产物。
- 拒绝方案：现在默认 LLM，扩大范围；全手工标题，维护重。
- 未决项：Task 2 的模型、提示词和质量门禁。
- Supersedes：none。

### D-06：读者页与审计数据分层

- 问题与最终选择：正式托管主题页直接服务读者；根 `Home.md` 和分类索引负责导航；`_digest`、`_queues`、归档只保留审计职责，不复制第二份知识正文。
- 推荐状态：方向审查提出，grill 通过 ADR 固化；避免读者进入内部文件，也避免双份内容漂移。
- 大白话：人从首页读知识，系统从内部目录查证据，两边是同一份正式知识，不复制。
- 来源：方向审查 finding“Reader-entry vs audit/quality surfaces”；grill 结论与 ADR 0004。
- 事实与约束：现有 `_digest/source-index.md` 是唯一导航；Claim、Evidence、Provenance 不能删除。
- 推理：可读入口缺失 → 在正式页之上增加导航 → 保留审计目录 → 不复制内容。
- 影响：`kb.structure.md`、pipeline 导航生成、页面模板、文档与验收。
- 后果与风险：读者导航必须只链接可读托管路径；内部目录不作为使用说明。
- 拒绝方案：复制读者投影，易漂移；继续以 `_digest` 为入口，不可读。
- 未决项：无。
- Supersedes：none。

## 三轮 talk

- Round 1：确认新库直发、旧库更新和托管删除权属。
- Round 2：确认日常只增改、稳定 ID 与可读展示名分离。
- Round 3：采纳方向审查，移除删除能力并把默认 LLM 命名移到 Task 2。

## 调研

外部调研跳过：本任务只处理本地 Markdown 发布合同；不存在待核实的外部接口。原始设计、参考知识库、现有代码和离线产物已完成本地事实审查。

## grill

`CONTEXT.md` 已更新：新增托管知识页、读者入口、发布结构。ADR 0004 已创建：读者发布与审计数据分层。术语冲突已解决：既有“结构约定”继续定义 Why/版本字段；“发布结构”定义托管和导航规则。

## 审查处置

方向盲审由 `pi/k3`、`cursor/grok`、`antigravity/flash` 完成，结果为 `revise_required`。重大问题已处置：删除能力移出 Task 1；离线标题来源和稳定路径已确认；读者入口明确为覆盖正式主题页的导航层，不替换审计质量合同。审查关于“历史 116 页是否托管”的问题不作为自动迁移授权；它们只作回归样本。

## 最终确认

待用户在本决策日志、详细审查完成后做一次正式批准。

## 拒绝方案

- 任意旧库文件可自动改写或删除：无明确权属，风险过高。
- 日常输入缺失即删除：日常输入不是全量事实。
- LLM 默认命名放进 Task 1：破坏离线、可重复、低风险交付。
- 复制一套读者正文：双份内容会漂移。

## 风险

- 首发标题受原始资料质量限制；Task 2 才改善语义质量。
- 不删除旧页意味着分页收缩需要明确无丢失表现规则。
- 旧库若未声明托管目录或缺少托管标记，必须失败而不是猜测。

## 未决项

- 分页收缩时旧页采用导航移除还是托管跳转页；build-spec 必须选择并提供无丢失测试。
- Task 2 的 LLM 默认命名合同和真实 provider 验收。

## Supersedes

- “仅在显式全量对账时删除”已被 D-03 替代。

## 文档结果

- `CONTEXT.md`：changed，记录发布领域术语。
- ADR 0004：created，记录读者与审计数据分层。
- `AGENTS.md`：no change，当前文件描述已实现系统；实现阶段改变正式输出后同步更新。

## Exit checks

- 外部接口：不适用；Task 1 不调用外部接口。
- 唯一字段与路径：`managed_by: KnowledgeDigest`、`digest_topic_id` 和首次锁定路径将由 `kb.structure.md` 与托管页头定义，build-spec 固化唯一格式。
- 失败语义：未声明托管目录、未标记页面、路径冲突或不安全路径必须失败。
- 范围：只发布、导航、新增和更新；不删除、不调用 LLM/embedding、不引入重型基础设施。
